# Contributing to BZiPS

Contributions are welcome through issues and pull requests. You do not need direct write access.

## Propose a change

1. For a new project or substantial change, open an issue describing the audience, purpose, and required tools.
2. Fork this repository and create a branch for your change.
3. Keep each project under `projects/<project-name>/`, using lowercase, hyphenated folder names.
4. Update the project documentation and any corresponding website content under `docs/`.
5. Open a pull request describing the change, its intended users, and what you actually tested.

Maintainer review is required before changes are merged. Submission does not guarantee acceptance.

## Project contents

Include a project README with purpose, supported tools, prerequisites, setup, and limitations. Add starter prompts, follow-up prompts, templates, and fictional examples in clearly named files as they become available.

Use these labels consistently:

- **Coming soon:** a reserved project; no usable prompt is published.
- **Draft:** published content that has not yet been validated for its stated workflow.
- **Tested:** validated for a named tool/version and scenario, with a last-tested date and known limitations.

Do not claim a prompt works with every AI tool or connector without evidence. Separate suggested workflows from features a tool actually supports.

## Content and licensing

Submit only content you have the right to share under the repository's MIT license. Use fictional or sanitized examples, not real contact records, private communications, secrets, or confidential business data.

Do not fabricate source references, supported capabilities, or testing results. Keep feedback respectful and focused on the work.

## Website checks

Preview using the README command. Check navigation, search, keyboard access, mobile layout, and copy buttons for any prompts you add. Keep the catalog and project pages consistent with the actual project files.

Record meaningful project changes in that project's version history. Correct or relabel stale tested claims when prerequisites or tools change.
